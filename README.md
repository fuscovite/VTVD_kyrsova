# СТО Master

Навчальний вебзастосунок для онлайн-запису клієнтів автомобільної станції технічного обслуговування. Проєкт створено в межах дисципліни «Веб-технології та вебдизайн».

## Технології

- PHP 8.2+ і Laravel 12;
- Blade-шаблони та Bootstrap 5;
- MySQL 8+ або SQLite;
- Laravel Eloquent, міграції та сидери;
- Laravel Form Request, CSRF middleware і сесійна авторизація;
- PHPUnit feature-тести.

## Можливості

- перегляд каталогу послуг і OEM-запчастин;
- створення заявки з серверною валідацією і CSRF-захистом;
- захищена сторінка адміністратора зі списком заявок;
- міграції та початкові демонстраційні дані;
- автоматизовані сценарії для публічної частини, заявки та доступу адміністратора.

## Швидкий запуск

1. Встановіть PHP 8.2+, Composer і MySQL 8+. Для локальної демонстрації також можна використати SQLite — це не потребує встановлення сервера MySQL.
2. Перейдіть до папки проєкту:

   ```bash
   cd service-laravel
   ```

3. Створіть локальний файл налаштувань і встановіть PHP-залежності:

   ```bash
   copy .env.example .env
   composer install
   php artisan key:generate
   ```

   Якщо Composer не додано до змінної `PATH`, виконайте ті самі команди через файл Composer:

   ```powershell
   php tools/composer.phar install
   php artisan key:generate
   ```

4. Для MySQL створіть базу даних `sto_master` у кодуванні `utf8mb4` і внесіть у `.env` параметри підключення:

   ```dotenv
   DB_CONNECTION=mysql
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_DATABASE=sto_master
   DB_USERNAME=root
   DB_PASSWORD=
   ```

   Для найпростішого локального запуску замість цього залиште стандартні параметри SQLite у `.env` і створіть порожній файл `database/database.sqlite`.

5. Створіть структуру бази та тестові дані:

   ```bash
   php artisan migrate:fresh --seed
   ```

6. Запустіть застосунок:

   ```bash
   php artisan serve
   ```

   Відкрийте `http://127.0.0.1:8000`.

## Тестування

Виконайте:

```bash
php artisan test
```

У тестах перевіряються доступність публічних сторінок, створення й валідація заявки, обмеження доступу до адмін-панелі та доступ авторизованого користувача. Фактичні результати перевірок фіксуються у `docs/TEST_RESULTS.md`.

## Структура

- `app/Models` — моделі предметної області;
- `app/Http/Controllers` — контролери публічної й адміністративної частин;
- `app/Http/Requests` — серверна валідація заявки;
- `database/migrations` — відтворювана структура бази даних;
- `database/seeders` — початкові дані;
- `resources/views` — Blade-шаблони;
- `tests/Feature` — автоматизовані функціональні тести;
- `docs` — протокол тестування та сценарій відеопрезентації.
