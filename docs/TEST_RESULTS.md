# Протокол тестування

Локальна перевірка виконана 14.10.2026 після команд `php artisan migrate:fresh --seed` і `php artisan serve`. Для HTTP-перевірок використано запущений застосунок за адресою `http://127.0.0.1:8000`.

| № | Сценарій | Очікуваний результат | Фактичний результат |
|---|---|---|---|
| 1 | Відкриття головної сторінки, каталогів і форми запису | Сервер повертає HTTP 200 | Виконано: `/`, `/services`, `/parts`, `/booking` — HTTP 200 |
| 2 | Надсилання валідної заявки | Запис створено в таблиці `bookings`, користувача повернуто до форми | Виконано: тестову заявку прийнято, HTTP 302; у таблиці `bookings` наявний 1 запис |
| 3 | Надсилання порожньої або помилкової форми | Дані не збережено, показано повідомлення валідації | Виконано: помилкові дані повертають до форми (HTTP 302), запис не створено |
| 4 | Перехід до `/admin/bookings` без входу | Перенаправлення на `/admin/login` | Виконано: HTTP 302 |
| 5 | Вхід адміністратора та перегляд заявок | Після коректного входу доступна таблиця заявок | Виконано: вхід тестовим обліковим записом — HTTP 302, сторінка заявок — HTTP 200 |
| 6 | POST-запит без CSRF-токена | Laravel відхиляє запит кодом 419 | Виконано: HTTP 419 |

Автоматизовані перевірки описано у `tests/Feature/BookingFlowTest.php`. У поточному локальному середовищі Windows запуск PHPUnit блокується помилкою доступу `is_readable()` у встановленій збірці PHP, хоча міграції, сидер і ручні HTTP-сценарії виконуються. Після публікації репозиторію перевірки також запускаються у GitHub Actions на Linux через `.github/workflows/tests.yml`.
